คุณไม่ได้กำลังใช้เอเจนต์ของคุณ คุณคือลูปของมัน มันเขียน คุณอ่าน มันบอกว่า "เสร็จแล้ว" คุณตรวจสอบ มันทำอะไรพัง คุณอธิบายว่าอะไรพัง แล้วคุณก็พิมพ์อีกครั้ง เกือบทุกการตั้งค่าแบบ "อัตโนมัติ" บทความโต้แย้งว่า คือคนคนหนึ่งที่กำลังเงียบ ๆ ทำงานสามอย่างที่ระบบควรจะทำเอง: ให้โมเดลมีที่ทำงาน บอกมันว่าทำถูกหรือไม่ และตัดสินใจว่าจะเกิดอะไรขึ้นต่อไป งานสามอย่างนี้มีชื่อ Harness, Loop, Graph งานเขียนส่วนใหญ่จัดวางมันเคียงข้างกันเหมือนเครื่องมือสามชิ้นบนชั้น และนั่นคือเหตุผลที่มันรู้สึกสับสน มันไม่ใช่เมนู มันคือบันได แต่ละชั้นมีอยู่เพราะชั้นข้างล่างมันพังในแบบเฉพาะที่คาดเดาได้

บันไดนี้มีเจ็ดระดับ และมีตัวอย่างเดียวที่วิ่งตลอดทั้งเรื่อง: มีรายงานบั๊กเข้ามา และเอเจนต์ต้องแก้มันแล้วเปิด PR ระดับ 0 คือแชต — คุณคือทุกอย่าง และคุณคือคอขวดของทั้งสามงานพร้อมกัน ระดับ 1 ให้มือกับเอเจนต์: เชลล์ การเข้าถึงไฟล์ ตัวรันเทสต์ git นิยามที่สะอาดที่สุดในบทความอยู่ตรงนี้: เอาโมเดลออกจากแผนภาพสถาปัตยกรรมของคุณ แล้วทุกอย่างที่ยังอยู่บนหน้าคือ harness ระดับ 2 เพิ่มความจำและกำแพง: สถานะที่อยู่ได้นานกว่าหน้าต่างบริบท และข้อจำกัดที่ไม่ขึ้นอยู่กับว่าโมเดลจะประพฤติตัวดีหรือไม่ "กำแพงไม่ใช่คำสั่ง 'กรุณาอย่าแตะ migrations' คือความปรารถนา สิทธิ์ที่เอเจนต์ไม่มีคือกำแพง" ระดับ 3 เพิ่มลูปที่มีการตรวจสอบที่อาจล้มเหลวได้ — และส่วนเดียวที่สำคัญคือการตรวจสอบ เพราะถ้าไม่มีมัน "ทำซ้ำ" ก็แค่หมายถึง "ทำผิดซ้ำ" การตรวจสอบแข็งแกร่งเท่ากับสิ่งที่อ่อนแอที่สุดที่มันยอมรับเป็นหลักฐานเท่านั้น และถ้าลูปของคุณยอมรับว่า "โมเดลบอกว่าเสร็จแล้ว" ลูปของคุณก็คือการรายงานตัวเอง ระดับ 4 เพิ่มผลป้อนกลับที่ลู่เข้า: สิ่งที่คาดไว้เทียบกับสิ่งที่เห็น รั้วรอบความพยายามครั้งต่อไป ทางตันที่ทำให้ความพยายามครั้งที่สามไม่สามารถเงียบ ๆ กลายเป็นความพยายามครั้งที่หนึ่งอีก และทางออก — ผลลัพธ์เดียวกันสองครั้งหมายถึงหยุดและยกระดับ เพราะสิ่งที่ขาดหายไปไม่ใช่ความพยายาม "ลูปแก้ งาน ได้ ลูปแก้ คำถาม ไม่ได้" ระดับ 5 เพิ่มกราฟ: โหนด การพึ่งพากันจริง ประตูที่งานออกจากโหนด ลูกศรส่วนใหญ่ในเวิร์กโฟลว์ไม่ใช่การพึ่งพากัน แต่เป็นนิสัย ระดับ 6 เพิ่มประตูและเส้นทางย้อนกลับ: แช่แข็งสิ่งที่ผ่านแล้ว รันใหม่เฉพาะสิ่งที่ล้มเหลว และตั้งประตูตามราคาของการย้อนกลับ ไม่ใช่ตามความมั่นใจ การพิมพ์ผิดในเอกสารส่งได้เมื่อไฟเขียว ส่วน migration ต้องใช้มนุษย์ ระดับ 7 คือการเรียนรู้: ทุกความล้มเหลวเป็นของชั้นหนึ่ง และบทเรียนจะติดก็ต่อเมื่อมันลงบนชั้นที่เป็นเจ้าของมัน บทเรียนคือข้อจำกัด ไม่ใช่บันทึกการสนทนา

นี่คือกรอบความคิดเกี่ยวกับระบบเอเจนต์ที่ชัดเจนที่สุดเท่าที่ผมเคยอ่าน และส่วนใหญ่ถูกต้อง ความแตกต่างทำงานได้จริง: harness คือสิ่งที่เอเจนต์ทำได้ loop คือสิ่งที่เป็นจริง graph คือสิ่งที่จะเกิดขึ้นต่อไป learn คือสิ่งที่ไม่เกิดขึ้นซ้ำ บันไดหลักฐาน — การทดสอบแบบกำหนดได้ แล้วสิ่งที่สังเกตได้ แล้วสิ่งที่โมเดลเห็น แล้วการรายงานตัวเอง ซึ่งไม่ใช่การตรวจสอบเลย — คือหน้าที่มีประโยชน์ที่สุดในบทความ ระดับราคาของการย้อนกลับคือวิธีที่ถูกต้องในการตัดสินใจว่ามนุษย์อยู่ตรงไหน: ใช้ความสนใจของคุณเฉพาะตรงที่การย้อนกลับไม่มีอยู่จริง และการวินิจฉัยตอนท้าย — หาอาการแรกของคุณจากด้านบน นั่นคือระดับถัดไปของคุณ ไม่ใช่ระดับถัดจากนั้น — คือบรรทัดที่ใช้ได้จริงที่สุดของบทความ และอย่างเงียบ ๆ มันก็คือคำแนะนำเดียวกับพรอมต์ตรวจสอบจากก่อนหน้านี้ในชุดนี้: จดรายการก่อนแก้ และแก้ชั้นที่เป็นเจ้าของความล้มเหลว

มีขอบเขตสามประการ และมันสำคัญเพราะบทความนำเสนอบันไดนี้ราวกับเป็นกฎ

ประการแรก ขอบเขต ตัวอย่างทุกตัวอย่างในบทความคือซอฟต์แวร์: บั๊ก ชุดทดสอบ PR migration บันไดหลักฐานตั้งอยู่บนโลกที่มีคอมไพเลอร์และการทดสอบแบบกำหนดได้ ที่ซึ่งหลักฐานที่ "แข็งแกร่งที่สุด" มีอยู่ สำหรับงานที่ไม่มีคอมไพเลอร์ — การเขียน การออกแบบ กลยุทธ์ การเจรจา — ไม่มีการตรวจสอบแบบกำหนดได้ให้ปีนขึ้นไป และขั้นบนสุดของบันไดก็ไม่มีอยู่จริง กรอบความคิดนี้คือกรอบความคิดสำหรับเอเจนต์โค้ด มันไม่ได้บอกอย่างนั้น และผู้อ่านที่นำมันไปใช้กับทุกอย่างจะเข้าใจผิดว่าการไม่มีการทดสอบคือความล้มเหลวของความเข้มงวด ทั้งที่บางครั้งมันเป็นแค่งานคนละแบบ

ประการที่สอง กฎของบันไดเองก็งอได้ "คุณข้ามระดับไม่ได้" บทความกล่าว — แล้วสองย่อหน้าต่อมา "คุณออกแบบจากตรงกลาง" เขียนการตรวจสอบระดับ 3 ลงบนกระดาษก่อนสร้างอะไร และ "งานส่วนใหญ่เสร็จที่ระดับ 4" โดยไม่ต้องไปถึงยอด บันไดคือเครื่องมือวินิจฉัย ไม่ใช่กฎ ระดับ 0 ก็เพียงพอสำหรับคำถามครั้งเดียว บทความบอกเอง ความเคร่งครัดเป็นเพียงวาทศิลป์ กฎที่มีประโยชน์คือกฎที่นุ่มกว่า: ปีนขึ้นก็ต่อเมื่อความล้มเหลวที่ระดับปัจจุบันของคุณมีราคามากกว่าการสร้างระดับถัดไป

ประการที่สาม แบบทดสอบสุดท้ายเป็นวงกลม แบบทดสอบของระดับ 7 คือความล้มเหลวประเภทเดียวกันจะไม่ทำให้คุณเสียค่าใช้จ่ายสองครั้ง แต่ "ประเภทเดียวกัน" กำลังทำงานทั้งหมด ประเภทถูกนิยามหลังจากข้อเท็จจริง โดยคนที่ตัดสินใจว่าบั๊กนี้เหมือนกับของสัปดาห์ที่แล้วหรือไม่ ระบบสามารถผ่านแบบทดสอบได้ด้วยการวาดประเภทให้แคบ และล้มเหลวได้ด้วยการวาดอย่างซื่อสัตย์ แบบทดสอบคือความปรารถนาที่แต่งกายเป็นตัววัด เวอร์ชันที่ซื่อสัตย์อ่อนแอกว่าและยังคงควรต้องการ: ความล้มเหลวเดียวกัน ที่เรียกชื่อเดียวกัน ควรจะถูกลงทุกครั้งที่มันเกิดขึ้น

มีข้อสังเกตเล็ก ๆ อีกสองข้อ บทความกล่าวถึงฉบับเต็มในรูปแบบ PDF ที่แนบมากับโพสต์ แต่ไม่มี PDF ปรากฏบนโพสต์ที่โหลดมา ดังนั้นฉบับเต็มจึงเข้าถึงไม่ได้ และมันจบลงด้วยการโฆษณาช่อง Telegram — ช่องทางขาย เหมือนกับส่วนใหญ่ ข้อสังเกตทั้งสองไม่เปลี่ยนข้อโต้แย้ง ข้อโต้แย้งนี้ดีที่สุดในประเภทของมัน: harness ทำให้เอเจนต์มีความสามารถ loop ทำให้มันซื่อสัตย์ graph ทำให้มันเป็นระเบียบ การเรียนรู้ทำให้มันดีกว่าเมื่อวาน ข้ามชั้นหนึ่งไปแล้วคุณจะกลายเป็นชิ้นส่วนที่ขาดหายไป เป้าหมายไม่เคยเป็นเอเจนต์ที่ไม่ต้องการคุณ มันคือระบบที่ต้องการคุณเพียงครั้งเดียว ในที่ที่ถูกต้อง
